# 0.11.0

## Breaking changes

### Leiden clustering (`so.cluster.leiden`)

- On the CPU, `so.cluster.leiden` uses `graspologic_native.leiden`.
- `iteration_count` now counts Leiden iterations on the CPU, each starting from the previous partition, and defaults to 5. With `iteration_count=None`, it iterates until the modularity no longer improves, so no node can increase the modularity by changing its community.
- `use_gpu` defaults to `False`, because `cugraph.leiden` refines communities greedily, ignores `theta` ([rapidsai/cugraph#5724](https://github.com/rapidsai/cugraph/issues/5724)) and runs a single Leiden pass.

### Spatial weights (`so.spatial.spatial_weights`)

- `so.spatial.spatial_weights` returns a `libpysal.graph.Graph` instead of a `libpysal.weights.W`. A `Graph` is faster to build and makes esda's local and bivariate statistics much faster. It is immutable, so esda can no longer row-standardize weights in place.
- `so.spatial.autocorrelation`, `local_autocorrelation`, `bivariate_correlation`, `local_heteroskedasticity` and `so.data.anndata_from_array` accept a `Graph` or a `W` and give identical results for both. Without `spatial_weights`, they use queen contiguity weights as a `Graph`.
- `so.spatial.spatial_weights` no longer shows a progress bar.
- `so.data.anndata_from_array` stores `obsp["spatial_connectivities"]` as a `scipy.sparse.csr_array` instead of a `csr_matrix`.

## New features

- **Progress bar and deterministic fits for self-organizing maps.** `so.dimension.som(..., verbose=True)` shows a progress bar over the epochs of `fit`. With `deterministic=True`, `fit` gives the same map in every run on the GPU, where the per-node sums are otherwise added in a varying order, at up to about 1.8x the fitting time. The CPU is always deterministic.

## Performance

- **Faster spatial statistics.** With `Graph` weights, building the spatial weights of a 438 × 438 image takes about 0.4 s instead of 1.7 s, `local_autocorrelation` (`Moran_Local`, `G_Local`) and `bivariate_correlation(method="moran")` are about 8–10× faster per call, and `autocorrelation` is about 1.4× faster.
- **Faster Leiden.** A fixed `iteration_count` runs as a single `graspologic_native.leiden` call instead of one call per iteration, which converts the edge list only once.
- **Faster permutation t-tests.** `so.tool.get_stats(..., comparison="all", test="t", permutation_count=...)` permutes the group labels once per resample for all groups and markers and calculates the t-statistics from group moments, e.g., in 0.3 s instead of 13 s for 22,500 SOM nodes, 20 groups, 20 markers and 100 permutations. The p-values have the same null distribution as before, but are estimated from different random permutations. Other tests and comparisons still use `scipy.stats.permutation_test`.
- **Faster batch-balanced kNN graphs.** `so.neighbor.knn_graph.create(..., method="batch_balanced")` collects the edges with numpy instead of a Python loop over every neighbor, and deduplicates edges faster for all methods.

## Bug fixes

- **`so.spatial.bivariate_correlation(method="lee")` works.** It raised an error for any input, because esda's `Spatial_Pearson` received the weights object instead of a sparse matrix and the images were not flattened. It now uses row-standardized weights, as esda documents, and reports permutation p-values in `p_value` (`z_score` is NaN for `lee`).
- **`so.tool.get_stats` supports channel-last data with more than two dimensions.** It iterated over the second dimension instead of the channels, so, e.g., `som.get_nodes(flatten=False)` raised an `IndexError` or compared the wrong columns.
- **Permutation tests in `so.tool.get_stats` pass the test options on.** With `permutation_count`, `equal_variance` and `test_kwargs` were dropped, so, e.g., `equal_variance=False` permuted Student's instead of Welch's t-statistic. Their p-values change for `equal_variance=False` and any `test_kwargs`. The docstring also said that `equal_variance=None` uses Welch's t-test; it uses scipy's default, Student's t-test, which is unchanged.
- **`distance_max` works.** `so.neighbor.knn_graph.create(..., distance_max=...)` raised a `ValueError` for any data. It now connects every pair of distinct data points within `distance_max`.

## Dependencies

- fastersom 0.3.2 is required, which provides the progress bar and deterministic fits of `so.dimension.som`.
- graspologic-native 1.3.1 or newer is required for Leiden clustering on the CPU.
